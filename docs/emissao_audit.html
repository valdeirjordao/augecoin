3. Distribuição por Bloco

Divisão da Recompensa

80% vai para o líder (minerador) que propôs o bloco. 20% vai para uma das 5 contas desenvolvedoras em round-robin.

block_reward(block_number) → total_reward
developer_reward = total_reward × 20%
leader_reward = total_reward × 80%
Líder (80%)80.000.000 augesat

4. Código-Fonte Relevante

emission.rs — Função block_reward()

pub fn block_reward(block_number: u64) -> u64 {
    if block_number == 0 {
        return CT_FIRST_REWARD_AUGESAT;      // 100_000_000
    }

    let halvings = block_number / CT_NEW_LINE_REWARD_DECREASE;   // / 210_240
    let mut reward = CT_FIRST_REWARD_AUGESAT;                    // 100_000_000
    for _ in 0..halvings {
        reward /= 2;
        if reward < CT_MIN_REWARD_AUGESAT {   // 10_000_000
            return CT_MIN_REWARD_AUGESAT;
        }
    }
    if reward < CT_MIN_REWARD_AUGESAT {
        CT_MIN_REWARD_AUGESAT
    } else {
        reward
    }
}

6. Fluxo de Execução do Bloco

// execute_block() em execution.rs

for each operation:
    verify_signature()           → paralelo
    execute_operation()           → sequencial, coleta fees

reward = block_reward(block_number)    → calcula por halving
dev_reward = reward × 20%              → developer_reward()
leader_reward = reward × 80%           → developer_leader_reward()

dev_account = developer_account_for_block(block_number)
credit(dev_account, dev_reward + fees) → dev recebe 20% + todas as taxas
credit(leader, leader_reward)          → líder recebe 80%

create_5_new_accounts()          → CT_ACCOUNTS_PER_BLOCK = 5
compute_safe_box_hash()          → novo hash do estado
commit()                         → atômico

7. Conclusão da Auditoria

Constantes que batem com o whitepaper:
  • ONE_AUGE = 100.000.000 (8 decimais) ✅
  • TOTAL_SUPPLY_AUGE = 750.000.000 ✅
  • CT_DEVELOPER_REWARD_PERCENT = 20 ✅
  • CT_DEVELOPER_ACCOUNT_COUNT = 5 ✅
Divergências críticas com o whitepaper:
  • TOTAL_EMISSION_BLOCKS — NÃO EXISTE
  • BASE_REWARD_AUGESAT — NÃO EXISTE
  • REMAINDER_AUGESAT — NÃO EXISTE
  • Modelo de emissão: whitepaper usa recompensa fixa, código usa halving
  • Emissão do whitepaper é finita (26.298.000 blocos), código é perpétua
  • TOTAL_SUPPLY_AUGESAT é definido mas nunca é usado como hard cap
  • O valor 2.852.383 no whitepaper não é o BASE_REWARD correto nem aparece no código
